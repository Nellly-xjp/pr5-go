# Практична робота № 5
## Розробка REST-сервісу на базі фреймворку Gin та СУБД PostgreSQL (Incident Tracker API)

**Виконала:** Тирканич Корнелія, група КН-41

---

## Мета роботи

- Опанувати принципи розробки високопродуктивних вебсервісів на базі фреймворку **Gin** (`gin-gonic/gin`) та навчитися працювати з контекстом запиту `*gin.Context`.
- Навчитися застосовувати декларативну валідацію вхідних DTO за допомогою тегів структури `binding` (`go-playground/validator`).
- Опанувати підключення до реляційної СУБД **PostgreSQL**, проєктування моделей даних та виконання CRUD-операцій через ORM-бібліотеку **GORM**.
- Засвоїти криптографічне хешування паролів за допомогою алгоритму **bcrypt** та реалізувати випуск підписаних **JWT-токенів** (`golang-jwt/jwt/v5`).

## Реалізована функціональність

### Рівень 1. Базовий: Gin-застосунок, PostgreSQL та валідація DTO

**1. Ініціалізація проєкту**

Створено Go-модуль `pr-5-go` та підключено необхідні бібліотеки для роботи з вебфреймворком Gin, ORM GORM і PostgreSQL.

**2. Підключення до PostgreSQL та створення моделей**

- Налаштовано підключення до локальної бази даних `incidents_db` у файлі `database/db.go`.
- Реалізовано перевірку підключення до бази даних.
- Створено модель `Incident`, яка містить такі поля:
  - `ID` — унікальний ідентифікатор;
  - `Title` — заголовок інциденту;
  - `Description` — опис проблеми;
  - `Priority` — пріоритет;
  - `Status` — поточний статус;
  - `CreatedAt` — дата створення.
- Встановлено значення статусу за замовчуванням `open`.
- Виконано автоматичну міграцію таблиці за допомогою `db.AutoMigrate(&models.Incident{})`.

**3. Валідація DTO та базові ендпоінти**

Створено `CreateIncidentDTO` із правилами валідації:

- `required` — обов'язкове поле;
- `min=3` — мінімальна довжина заголовка;
- `max=100` — максимальна довжина заголовка;
- `oneof=low medium high critical` — дозволені значення пріоритету.

Реалізовано такі маршрути:

| Метод | Маршрут | Опис |
|---|---|---|
| POST | `/api/v1/incidents` | Створення нового інциденту |
| GET | `/api/v1/incidents` | Отримання списку інцидентів |

У разі помилки валідації сервер повертає `400 Bad Request` із переліком помилкових полів. У разі успішного створення повертається `201 Created`.

### Рівень 2. Ключовий: Повний CRUD та автентифікація (JWT)

**1. Повний життєвий цикл інцидентів**

Реалізовано повний набір CRUD-операцій для управління технічними інцидентами.

| Метод | Маршрут | Опис | HTTP-статус |
|---|---|---|---|
| POST | `/api/v1/incidents` | Створення інциденту | 201 |
| GET | `/api/v1/incidents` | Отримання всіх інцидентів | 200 |
| GET | `/api/v1/incidents/:id` | Отримання інциденту за ID | 200 / 404 |
| PATCH | `/api/v1/incidents/:id/status` | Оновлення статусу | 200 / 400 / 404 |
| DELETE | `/api/v1/incidents/:id` | Видалення інциденту | 204 / 404 |

Для зміни статусу реалізовано перевірку допустимих значень:

- `open` — відкритий;
- `in_progress` — у процесі виконання;
- `resolved` — вирішений;
- `closed` — закритий.

**2. Модель користувача та безпека**

Створено модель `User` із такими особливостями:

- поле `Email` має унікальний індекс;
- поле `PasswordHash` використовується для зберігання хешу пароля;
- тег `json:"-"` приховує хеш пароля під час формування JSON-відповідей;
- виконано автоматичну міграцію таблиці `users`.

**3. Сервіс автентифікації**

Реалізовано два маршрути для роботи з обліковими записами.

| Метод | Маршрут | Опис |
|---|---|---|
| POST | `/api/v1/auth/register` | Реєстрація нового користувача |
| POST | `/api/v1/auth/login` | Вхід у систему та отримання JWT |

Особливості реалізації:

- перевірка правильності email;
- перевірка мінімальної довжини пароля (6 символів);
- хешування пароля за допомогою `bcrypt.GenerateFromPassword`;
- перевірка пароля через `bcrypt.CompareHashAndPassword`;
- повернення `401 Unauthorized` у разі неправильних облікових даних;
- генерація підписаного JWT-токена з алгоритмом `HS256`;
- встановлення строку дії токена — 24 години.

## Інструкція із запуску проєкту

### 1. Підготовка PostgreSQL

Переконайтеся, що сервер PostgreSQL запущено та створено базу даних:

```sql
CREATE DATABASE incidents_db;
```

У файлі `database/db.go` необхідно вказати актуальні параметри підключення:

- Host — `localhost`;
- Port — `5432`;
- User — ваш користувач PostgreSQL;
- Password — ваш пароль;
- DBName — `incidents_db`.

### 2. Встановлення залежностей

Відкрийте термінал у папці проєкту та виконайте:

```bash
go mod tidy
```

Команда завантажить необхідні залежності та оновить файли `go.mod` і `go.sum`.

### 3. Запуск сервера

```bash
go run main.go
```

Після успішного запуску сервер буде доступний за адресою:

```text
http://localhost:8080
```

## Довідник API та приклади тестування (cURL)

Для тестування API можна використовувати термінал, PowerShell або програму Postman.

### 1. Управління інцидентами

**Створення нового інциденту (201 Created)**

```bash
curl -X POST http://localhost:8080/api/v1/incidents \
  -H "Content-Type: application/json" \
  -d '{"title":"Втрата зв’язку з вузлом","description":"Немає відповіді від шлюзу в сегменті А","priority":"high"}'
```

**Перевірка валідації (400 Bad Request)**

Приклад запиту з неправильним пріоритетом та некоректним заголовком:

```bash
curl -X POST http://localhost:8080/api/v1/incidents \
  -H "Content-Type: application/json" \
  -d '{"title":"А","description":"","priority":"urgent"}'
```

**Отримання списку всіх інцидентів (200 OK)**

```bash
curl http://localhost:8080/api/v1/incidents
```

**Отримання інциденту за ID (200 OK або 404 Not Found)**

```bash
curl http://localhost:8080/api/v1/incidents/1
```

**Зміна статусу інциденту (200 OK)**

```bash
curl -X PATCH http://localhost:8080/api/v1/incidents/1/status \
  -H "Content-Type: application/json" \
  -d '{"status":"in_progress"}'
```

**Видалення інциденту (204 No Content)**

```bash
curl -X DELETE http://localhost:8080/api/v1/incidents/1
```

### 2. Автентифікація користувачів

**Реєстрація нового користувача (201 Created)**

```bash
curl -X POST http://localhost:8080/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"engineer@example.com","password":"secretpassword"}'
```

**Вхід у систему та отримання JWT-токена (200 OK)**

```bash
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"engineer@example.com","password":"secretpassword"}'
```

## Висновки

Під час виконання практичної роботи № 5 було розроблено RESTful вебсервіс для обліку та управління технічними інцидентами мовою програмування Go. Для створення API використано фреймворк **Gin**, а для роботи з базою даних — **PostgreSQL** та ORM-бібліотеку **GORM**.

У результаті було закріплено практичні навички розробки REST API, роботи з реляційними базами даних та реалізації базових механізмів безпеки вебзастосунків.
